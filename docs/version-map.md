# 版本对照 / Version Map

本仓库有两条**互不兼容**的固件产品线。它们共享同一块硬件，但不是同一份固件的不同版本，不能互相 OTA，也不能混用构建配置。

## 1. 一句话对照

| | v1.0.0 | v2.0.0 |
|---|---|---|
| 产品名 | 星芽小屋 · 果冻幽灵桌宠 | Desk Pet（Mosaico Instance） |
| 目录 | 仓库根目录：`firmware/`、`docs/`、`assets/` | [`v2-desk-pet/`](../v2-desk-pet/) |
| 核心玩法 | 接星星 | 三属性养成 + 泡泡点击 |
| 固件版本号 | 1.0.0 | 1.0.0（该谱系首个固件；仓库发布号为 v2.0.0） |

| LVGL | 9.6 | 9.5.0 |
| 许可 | MIT | Apache-2.0 |
| 固件产物 | `firmware/dist/` 预编译包 | 源码构建（`idf.py build` + `.irisfw`） |

## 2. 为什么版本号看起来“重复”

两个数字含义不同，必须分开写：

- **仓库发布版本（v1.0.0 / v2.0.0）**：整个仓库的发布里程碑，代表“哪一条产品线”。
- **固件版本（都是 1.0.0）**：各产品线内部自己的固件迭代号，运行时通过 ESP-Iris 的 `app_version` 与 `CONFIG_APP_PROJECT_VER` 读取。

因此“v2.0.0 / 固件 1.0.0”是完全正常的组合；升级 v2 固件时，固件号会走 1.0.1、1.1.0，而仓库发布版本只在换产品线或大版本时变动。

## 3. 硬件与外设差异

| 外设 | v1.0.0 | v2.0.0 |
|---|---|---|
| 屏幕 / 触摸 | CO5300 480×480 / CST9220 | 相同 |
| AI 键 | 使用 | 使用（喂食） |
| 右侧交互模块 | 未接入 | 接入：LDR、KEY_L/KEY_R、PIR、WS2812×6 |
| 光控睡眠 | 无 | 双阈值 + 3 s 确认 + 180 s 唤醒保护 |
| NVS 持久化 | 见 v1 文档 | `pet` 命名空间，`PTS1` 快照 + CRC16 |

## 4. 烧录前检查

1. 确认要刷的是哪条产品线（看目录，不看 `vX` 字样）。
2. 两者的 `partition` 布局与 ESP-Iris 契约不同：v2 使用 `mosaico-retained-test-2m-v2`、ABI 2、`main_app@0x210000`。
3. v2 的构建/烧录流程见 [v2-desk-pet/README.md](../v2-desk-pet/README.md) 第四、五章；v1 见根目录 README。
